# fix：tasks・walkに推奨モデルとエフォートを付ける

## 内容

グローバルルールの改訂（261106034223）で「推奨モデルとエフォート」が加わった。この計画はそれより前に作ったため、ルールの「推奨のない計画」に従って、未着手の項目に推奨を付けた。

- `planning_dialog/261105131844_tasks_sonar_spectra_initial.md`
  - Phase 2〜10の未着手の【エージェント】の項目（54件）に、`推奨: {モデル}・{エフォート}以上`を1段下げた最初の行として加えた
  - Phase 2〜10の見出しの直後に`Phaseの推奨`を加えた（Phase 9は`Opus・xhigh以上`、Phase 10は`Sonnet・high以上`、ほかは`Opus・high以上`）
  - Phase 11は【エージェント】の項目がないため、Phaseの推奨を書いていない
- `planning_dialog/261105131844_walk_sonar_spectra_initial.md`
  - Phase 2〜10の未着手の【エージェント】の項目（35件）に推奨を加えた

## 変えていないもの

- IDと順序、項目の内容、依存、チェック状態
- Phase 1（完了済み）の項目。完了済みの項目の推奨は付けない（実際に使ったモデルの記録もないため、実施メモにも書いていない）

## 見積もりの考え方

スキル`agentic-coding-agent`の「推奨モデルとエフォートの目安」に従った。迷ったものは上の段階にした。

- `Opus・high以上`：入力源・解析・送出・受信・描画ループなどRustとUIにまたがる基盤、自動整列と手動配置の配置規則、永続化（`settings_store`・ストア・構成の操作と書き出し・読み込み）、複数の画面で状態を共有する画面（設定パネル・レイアウト編集・インスタンスの設定・配色の管理）、CIのワークフロー、モックとの照合や計測のように判断の多い検証
- `Opus・xhigh以上`：T9-1（負荷の原因が特定できておらず、解析・送出・描画の複数層にまたがる調査と軽量化になるため）
- `Sonnet・high以上`：1つのモジュール・1つの部品で完結する画面の実装、単体テストの作成、i18nの自動検査と疑似ロケールでの確認、README・About欄・CHANGELOGなどのリリース準備
- `Sonnet・medium以上`：既存のギャラリーへの横展開、既にある部品のつなぎ込み、`CONTRIBUTING.md`の追記、手順どおりに実行して結果を見る検証

## 理由

ルールの改訂に計画を合わせ、項目ごとにモデルとエフォートを使い分けられるようにするため。要件・設計・インターフェース・タスク構成・プランアセットの確定事項は変えていないため、仕様変更ではなく軽微な修正として扱った。
