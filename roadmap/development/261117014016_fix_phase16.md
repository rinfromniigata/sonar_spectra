# fix（Phase 16）：Phase 16で見つけた軽微な修正の記録

## 1. 送出の間隔のテストが、CIのmacOSのランナーで回数不足で落ちる（T16-6のリリースのCI）

- 種別：軽微な修正（要件・設計・インターフェース・タスク構成・プランアセットの確定事項は変えない。テストの条件だけを直し、アプリのコードは変えない）
- 見つけた検証：T16-6の`release.yml`（run 43899804397）のmacOSのジョブの`bun run check`で、`frame_transport::tests::transport_sends_about_sixty_frames_per_second_and_applies_controls`が2回続けて落ちた（500msで17回・15回、平均の間隔は約30〜31ms。基準は20〜36回）。同じコミットのdevのCIと手元（8コア）では通る
- 関連タスク：T2-7（送出のスレッド）

### 内容

- 原因：テストは`Pipeline::default()`（すべての解析が有効）で送出を始めていた。デバッグビルドのテストを並列に回すと、CIのmacOSのランナー（arm64、3コア）では1回の解析が16.7msを超え、送出のスレッドは遅れを取り戻さずに数え直す作りのため、回数が半分近くに落ちた。テストが測りたいのは送る間隔で、解析の速さではない（解析の負荷は、Phase 15でリリースビルドを実機で測っている）

### 修正

- `src-tauri/src/frame_transport/mod.rs`（テストのみ）：`FrameTransport::start_with`で、軽いレベルとVUだけを有効にして始める。回数の基準（20〜36回）と、セクションの切り替え・一時停止・再開・停止の確かめは変えない

### 確認

- 手元で、そのテストが30回（平均16.66ms）で通る
- 16個の`yes`でCPUをふさいだ状態で、`cargo test --lib`を3回回し、すべて通過（30〜31回、平均16.66〜16.76ms）
- `bun run check`が通る
- CIのmacOSのランナーでの通過は、タグを付け直したあとのリリースのCIで確かめる

## 2. リリースのCIのmacOSのビルドで、actoolが落ちてAssets.carを作れない（T16-6のリリースのCI）

- 種別：軽微な修正（要件・インターフェース・タスク構成・プランアセットの確定事項は変えない。imple 7節に「既知の不具合に当たったときは、事前に`actool`で作った`Assets.car`を`bundle.icon`に入れる」と決めてある手に切り替えた。`AppIcon.icon`とマスターSVGは変えていない）
- 見つけた検証：T16-6の`release.yml`（run 43910600761、job 133451143102）。検査は通り、`tauri build`の`.app`のバンドルで「Failed to create app Assets.car: failed to run actool … -[__NSPlaceholderArray initWithObjects:count:]: attempt to insert nil」で止まった（tauri#15315と同じ。ランナーはXcode 26.6）。手元（Xcode 27.2）では起きない。Windowsのジョブは成功
- 関連タスク：T14-9（`.icon`のビルドへの組み込み）、T16-1

### 内容

- 原因：tauri-bundlerが`bundle.icon`の`.icon`をビルドの中で`actool`にかけるところで、GitHub Actionsのランナーでは`actool`が落ちる（tauri#15315は未解決。同じissueに、手で実行すると通る・標準入力が閉じていると失敗する・前回の失敗で残った`ibtoold`が次も失敗させる、という報告がある）。手元で再現しないため、ランナーで`actool`を直す道は取らなかった

### 修正

- `scripts/app_icon_car.ts`・`scripts/app_icon_car_core.ts`（とテスト）を足した。`bun run icons:car`（macOSのみ）は、`AppIcon.icon`を一時フォルダーへ`Icon.icon`として写し、tauri-bundler 2.10.4と同じ引数で`actool`にかけ（標準入力は/dev/null）、`src-tauri/macos/Assets.car`と、元にした`AppIcon.icon`の指紋（改行と区切り文字をそろえたSHA-256）`Assets.car.source`を書く。`bun run check:appicon`（`--check`。OSを問わない）は、指紋が今の`AppIcon.icon`と一致することを確かめ、`bun run check`に入れた
- `src-tauri/tauri.macos.conf.json`：`bundle.icon`の`macos/AppIcon.icon`を`macos/Assets.car`に替えた（`.car`はバンドラーがそのまま使い、`actool`を呼ばない。`CFBundleIconName`は`assetutil`で`.car`から読む）
- `.gitattributes`：`Assets.car`をbinaryにした
- `CONTRIBUTING.md`・`release.yml`のコメント：`Assets.car`を手元で作る形と、`AppIcon.icon`の作り直しの手順（`bun run icons:car`を足した）に改めた

### 確認

- 作った`Assets.car`の`Icon Image`の名前が`Icon`である（`assetutil --info`）
- `bun run tauri build --target aarch64-apple-darwin --bundles dmg`で`.dmg`ができ、マウントした中の`.app`の`Assets.car`が`src-tauri/macos/Assets.car`とバイト単位で一致、`icon.icns`あり、`CFBundleIconName`＝Icon、署名はadhoc
- `bun run check`が通る（`check:appicon`を含む。単体テスト987件）
- 残る確かめ：CIのmacOSのランナーでのビルドの通過は、タグを付け直したあとのリリースのCIで。`Assets.car`は手元のXcode 27.2の`actool`で作った（`--minimum-deployment-target 26.0`）。macOS 26の実機での見え方は確かめられていない（開発機はmacOS 27）
