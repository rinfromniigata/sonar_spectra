# fix（Phase 16）：Phase 16で見つけた軽微な修正の記録

## 1. 送出の間隔のテストが、CIのmacOSのランナーで回数不足で落ちる（T16-6のリリースのCI）

- 種別：軽微な修正（要件・設計・インターフェース・タスク構成・プランアセットの確定事項は変えない。テストの条件だけを直し、アプリのコードは変えない）
- 見つけた検証：T16-6の`release.yml`（run 43899804397）のmacOSのジョブの`bun run check`で、`frame_transport::tests::transport_sends_about_sixty_frames_per_second_and_applies_controls`が2回続けて落ちた（500msで17回・15回、平均の間隔は約30〜31ms。基準は20〜36回）。同じコミットのdevのCIと手元（8コア）では通る
- 関連タスク：T2-7（送出のスレッド）

### 内容

- 原因：テストは`Pipeline::default()`（すべての解析が有効）で送出を始めていた。デバッグビルドのテストを並列に回すと、CIのmacOSのランナー（arm64、3コア）では1回の解析が16.7msを超え、送出のスレッドは遅れを取り戻さずに数え直す作りのため、回数が半分近くに落ちた。テストが測りたいのは送る間隔で、解析の速さではない（解析の負荷は、Phase 15でリリースビルドを実機で測っている）

### 修正

- `src-tauri/src/frame_transport/mod.rs`（テストのみ）：`FrameTransport::start_with`で、軽いレベルとVUだけを有効にして始める。回数の基準（20〜36回）と、セクションの切り替え・一時停止・再開・停止の確かめは変えない

### 確認

- 手元で、そのテストが30回（平均16.66ms）で通る
- 16個の`yes`でCPUをふさいだ状態で、`cargo test --lib`を3回回し、すべて通過（30〜31回、平均16.66〜16.76ms）
- `bun run check`が通る
- CIのmacOSのランナーでの通過は、タグを付け直したあとのリリースのCIで確かめる
