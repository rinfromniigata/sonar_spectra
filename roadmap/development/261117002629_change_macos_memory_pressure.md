# change：macOSで、VJツールと同時に動かすときのメモリの基準を改める

- 種別：仕様変更（非機能要件〔SPEC 3節「macOSでの負荷の確かめ方」の30分の確かめの基準〕と、walkのW15-3の基準を変える）
- 状態：**承認済み（261117）**。ユーザーの回答は「はい、承認します」
- 反映（261117002930）：specsをv11に、imple・tasks・walkを`261117002930_*`にした
- 発端：W15-3（261116〜261117）。ユーザーが2回確かめ、どちらもメモリプレッシャーが黄色になった。SPEC 3節（v10）は「黄色にならない」ことを求め、満たせないときは仕様変更として扱うと定めている。ユーザーの判断は「開発機のメモリが8GBと少なく、この環境でVJをする人はまずいないので、良いことにする」

## 現状（v10）と確かめた結果

- SPEC 3節：「VJツールと同時に30分（「等倍」・上限30fps）動かし、音と表示のずれ・VJツール側の重さが気にならず、アクティビティモニタのメモリプレッシャーが黄色にならない」
- 1回目：TouchDesignerの重めのプロジェクトと同時に30分。著しいカクつきはなかった。メモリプレッシャーはずっと黄色（物理8GB・使用済み7.25GB・スワップ4.74GB・圧縮2.02GB）。直後の`state.json`は「画面どおり」・上限60で、条件と違っていた可能性がある
- 2回目：「等倍」・上限30fpsで30分以上。メモリプレッシャーは大半が緑で、終わりのほうで黄色になった（赤にはならなかった。物理8GB・使用済み7.04GB・スワップ4.37GB・圧縮2.03GB）。1回目より負荷は低かった。同時に動いていたものに、rust-analyzer（1.26GB）がある。Sonar Spectraの描画のプロセス（`localhost:1420`）は460MBで、開発用のビルド（`bun tauri dev`）で動かしていた
- Sonar Spectra自体のメモリ（リリースビルド・「等倍」・上限30・全画面・全モジュール、起動25秒後の`footprint`）：合計約0.57GB（本体34MB・WebKitのGPU 81MB・WebContent 442MB・Networking 8MB）
- 見立て：黄色になった主な原因は、メモリ8GBの開発機で、Sonar Spectra以外のもの（重いVJプロジェクト、エディタと開発の道具）が多くのメモリを使っていること。Sonar Spectraの分は1割に満たない

## 変更内容

### 1. SPEC 3節「macOSでの負荷の確かめ方」の30分の確かめの基準を改める

- 改める前：「…音と表示のずれ・VJツール側の重さが気にならず、アクティビティモニタのメモリプレッシャーが黄色にならない」
- 改めた後：「…音と表示のずれ・VJツール側の重さが気にならず、アクティビティモニタのメモリプレッシャーが赤にならない。開発機はメモリ8GBのため、VJツールやほかのアプリと同時に動かすと黄色になることは許す（Sonar Spectra自体のメモリは記録する）」
- ほかの基準（「等倍」・上限30fpsで上限に届くこと、App Napの抑止）は変えない

### 2. 計画への反映

- walk（Phase 15）
  - W15-3：基準を上の1に改める（「黄色にならない」→「赤にならない。黄色は許す」）。2回目の結果（「等倍」・上限30fpsで30分以上、カクつき・ずれ・VJツール側の重さは気にならず、メモリプレッシャーは赤にならなかった）で通過とし、チェックする。開発用のビルドで確かめた点は実施メモに残す
- tasks：変更なし（Phase 15の引き継ぎメモだけ更新する）

## 承認していただきたい点

1. SPEC 3節のメモリの基準を、上の1のとおり（赤にならない。8GBの開発機では黄色を許す）にしてよいか
