# fix：インスタンスの設定を開いた直後、下のほうのモジュールでポップオーバーが上へずれる（W6-4の検証中）

- 種別：軽微な修正（要件・設計・インターフェース・タスク構成・プランアセットの確定事項は変えない。置き場所の規則〔popover_position.ts〕はそのままで、置くときの測り方を直した）
- 見つけた検証：W6-4（疑似ロケールでのインスタンスの設定の確認）
- 関連タスク：T6-1（インスタンスの設定のポップオーバー）、T6-4（歯車ボタンから開く）

## 内容

W6-4で、疑似ロケール（`bun x vite --mode pseudo`）のアプリを、ヘッドレスのEdgeでChrome DevTools Protocolから操作して測ったところ、画面の下のほうにあるモジュール（スペクトラム・スペクトログラム・ラウドネスなど）の歯車から設定を開くと、ポップオーバーがモジュールの横ではなく、画面の上のほう（領域の上端の下限）に出ていた。配色などを1回変えると、置き直しで正しい位置（モジュールの横、下端に収まる位置）へ移った。

- 例：1920×1080のラウドネス（枠の上端は約825px）で、開いた直後は上端133px、配色を変えたあとは698px
- 上のほうのモジュール（レベル・波形）では、どちらの場合も元の上端にそろうため、ずれは出ない

原因は、`UiPopover.vue`が最初に置くとき、幅がまだ0pxの状態で高さ（`offsetHeight`）を測っていたこと。幅0では文が1文字ずつ折り返して、高さが上限（`--popover-max-height`）まで伸びるため、「下端に収まるように」上へ押し上げていた。置き直し（中身が変わったとき）では、すでに幅が付いているので正しく測れていた。疑似ロケールに限らず、通常の日本語でも同じ。

## 修正

- `src/components/ui/UiPopover.vue`
  - 置く処理を2回に分けた。1回目で幅を決め、次の描画のあとに高さを測り直して置く（幅は高さによらないので、2回目で幅は変わらない）。待つ間に閉じた・元や領域が変わったときは、2回目を行わず置き直しに任せる
  - ウィンドウの大きさの変化の見張りは、待つ前に登録する（開いてすぐ閉じたときに、見張りが残らないように）

## 確認

- 疑似ロケールで、既定の7つのモジュールすべてについて、960×600・1280×800・1920×1080の3つの大きさで、開いた直後の位置と配色を変えたあとの位置が一致することを測って確かめた（修正前は、下のほうのモジュールで食い違っていた）。スクリーンショット（1920×1080のラウドネス、960×600の波形）を目で見て、モジュールの横に出ていることを確かめた
- DOMのテスト環境がないため、この振る舞いの自動テストは足していない（置き場所の規則そのものは`popover_position.test.ts`が受け持つ）
- `bun run check`：終了コード0（UIのテスト572件・Rustのテスト114件）
