# fix：書き込みが失敗しても前の状態が残ることを、直接守るテストを足す（W4-1の検証中）

- 種別：軽微な修正（テストの追加だけで、`settings_store`の振る舞い・インターフェース・タスク構成・プランアセットの確定事項は変えない）
- 見つけた検証：W4-1（`settings_store`の単体テスト。観点：書き込みの途中で止めても前の状態が残る）
- 関連タスク：T4-1

## 内容

W4-1でテスト17件が通ることを確かめたあと、「書き込みの途中で止めても前の状態が残る」の観点が、テストで本当に守られているかを確かめた。`save`を、一時ファイルを使わず`state.json`に直接書く実装に一時的に書き換えると、既存の`interrupted_write_keeps_the_previous_state`は落ちたが、落ちた理由は最後の「保存後に一時ファイルが残らない」という付随の確認だった。書きかけの一時ファイルを手で置いて`load`するだけのテストなので、置き換え方式そのもの（書き込みに失敗しても前の`state.json`を触らない）は守られていなかった。直接書く実装に一時ファイルの掃除まで足した退行は、すり抜けるおそれがあった。

## 修正

- `src-tauri/src/settings_store/mod.rs`：テスト`failed_write_leaves_the_previous_state_untouched`を追加した。保存済みの`state.json`がある状態で、一時ファイルの場所を同じ名前のフォルダでふさぎ、`save`が`Io`エラーを返すこと、`state.json`のバイト列が保存前と同じであること、`load`で前の状態が読めることを確かめる。製品のコードは変えていない

## 確認

- 通常の実装で18件（既存17件＋追加1件）が通る
- `save`を「`state.json`に直接書き、一時ファイルを掃除する」実装に一時的に書き換えると、追加したテストだけが落ちる（既存17件は通る）。確かめたあと、元の実装に戻した
- `bun run check`は終了コード0で通った（UI 378件・Rust 114件）
