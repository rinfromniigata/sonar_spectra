# fix：狭い枠で、編集中の見出しが枠の幅からはみ出す（W5-5の検証中）

- 種別：軽微な修正（要件・設計・インターフェース・タスク構成・プランアセットの確定事項は変えない。見出しの寸法の振る舞いを、狭い枠で崩れないように直した）
- 見つけた検証：W5-5（疑似ロケールでの編集画面・一覧・見出しの確認）
- 関連タスク：T5-4（編集中のモジュールの見出し）

## 内容

W5-5で、疑似ロケール（`bun x vite --mode pseudo`）のアプリを、実ブラウザのEdgeで測ったところ、見出し（`EditHead`）が、狭い枠の幅からはみ出していた。既定の7つのモジュールで、次の枠があった。

- 疑似ロケール：1280×800のレベル（枠77px）、960×600のレベル（52px）とラウドネス（107px）
- 通常の日本語（疑似ロケールなし）でも、960×600（最小の幅）のレベル（52px）で同じ崩れが出た。疑似ロケールが約35%文言を伸ばすことで悪化していたが、原因は元からあった

はみ出していたのは、名前（「レベル 1」）・適合判定のバッジ・方向の矢印（4つのボタン）。名前とバッジは`white-space: nowrap`で、枠の幅より長くなると折り返さずに外へ出て、枠（`overflow: hidden`）に切られた。矢印の4つのボタンはひとかたまりで、枠の幅より広いと同じく切られていた。モックにも同じ作りがあるが、モックの既定の幅（約1200）では出会わない。

## 修正

- `src/components/EditHead.vue`
  - 名前とバッジに`min-width: 0`・`max-width: 100%`・`overflow: hidden`・`text-overflow: ellipsis`を付け、枠の幅で切って「…」にする。切られても読めるよう、`title`に全文を入れた
  - 方向の矢印のグループ（`.dirs`）に`flex-wrap: wrap`・`max-width: 100%`を付け、狭い枠では2段に折り返して収める
- `src/components/EditHead.test.ts`：名前とバッジに`title`が付くことのテストを1件追加

## 確認

- 疑似ロケール・通常の日本語とも、既定の7つで、1280×800・960×600・960×900のすべてで、見出しの部品が枠の幅からはみ出さず、枠の高さにも収まることを、実ブラウザで測って確かめた（修正前は、疑似ロケールで3か所、通常の日本語で1か所が落ちた）
- 保存が残っていた状態（レベルが4つに分かれ、枠が66pxの高さ）で測ると、折り返した見出しが枠の高さを超えることがあった。これは、枠そのものが見出しの高さに足りないほど小さい場合で、モックにも同じ作りがあり、対象外とした（無理に詰めると、矢印が押せなくなる）
- `bun run check`：終了コード0（UIのテスト529件・Rustのテスト114件）
