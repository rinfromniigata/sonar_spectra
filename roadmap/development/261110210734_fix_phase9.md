# fix（Phase 9）：Phase 9で見つけた軽微な修正の記録

## 1. 描画の層の図形が、枠の右・下ほど文字の層（移行前の描画）からずれる（T9-7の実機の確かめ中）

- 種別：軽微な修正（要件・設計・インターフェース・タスク構成・プランアセットの確定事項は変えない。imple 4.6の「方向：枠の quarterTurns を頂点の変換（行列）で当てる」の範囲で、行列の大きさの取り方を直した）
- 見つけた検証：T9-7の実機の確かめ（移行前の撮影 `sonar_spectra_captures\t9_5_canvas2d\shots` との比較）
- 関連タスク：T9-5（描画の層の方向の変換）

### 内容

T9-7で図形を描画の層へ移したあとの撮影を移行前と比べたところ、格子線や棒が、枠の左端では同じ位置なのに、右（下）へ行くほど最大 0.1〜0.9 デバイスピクセルずれていた（重心と変化量の細い棒は、枠の右半分で棒ごと違って見えた）。

- 原因：`frameClipMatrix`（`src/render/gl/transform.ts`）が、描画の座標系（枠の CSS の大きさ）を、ビューポート（画面上で丸めた枠の大きさ、デバイスピクセル）いっぱいに引き伸ばしていた。文字の層（移行前は図形も）は、CSS ピクセル × DPR の座標で、画素数が「枠の CSS の大きさ × DPR」を丸めたキャンバスに描かれ、画面上の枠の大きさに合わせて表示される。両者は 1 ピクセル違うことがあり（例：CSS の幅 479.25 × DPR 1.5 = 718.875 → キャンバスは 719 画素、画面上の枠は 718 デバイスピクセル）、その割合だけ拡大率がずれていた
- T9-5の時点では図形が文字の層に描かれていたため、比較に出なかった

### 修正

- `src/render/gl/transform.ts`：行列を「描画の座標系 → 文字の層のキャンバスの画素（CSS ピクセル × DPR、`directionTransform` と同じ）→ ビューポート全体」の順に写す形にした。キャンバスの画素数の丸めを `canvasPixels` として持ち、`frameClipMatrix` に DPR を渡す
- `src/render/gl/shape_layer.ts`：枠ごとの記録に DPR を持ち、行列に渡す
- `src/components/ModuleFrame.vue`：文字の層のキャンバスの画素数を `canvasPixels` で求める（丸めの正本を1つにした）
- `src/render/gl/transform.test.ts`：どの向きでも、文字の層のキャンバスの画素と同じ位置に写すこと、`canvasPixels` の丸めのテストを足した

### 確認

- 実機（リリースビルド・全画面 2880×1800・DPR 1.5）で、T9-7の撮影を移行前と比べ、差が 64/255 を超えるピクセルが `base` で 627→115、`dir_c` で 353→19（ダーク）に減った。残る差はふちのならし方（マルチサンプル）と線の角の付き方の違い（T9-7の実施メモ）
- `bun run check`が通る（UI 939件、Rust 144件）
